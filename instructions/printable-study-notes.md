# Printable study notes

Shared operating rules, loaded through [AGENTS.md](../AGENTS.md). Named rules in other modules are located through its rule map.

## Printable study notes

The media role supports a printable study note as a separate requested output alongside infographics, presentations and podcasts. Use the current wiki and the same curriculum-aware scope decision; producing a handout does not expand the compulsory lesson or trigger automatic generation of every format.

* **Teach from paper.** Plan a short topic introduction and learning goal, necessary concepts, connected explanations, worked examples where useful, a compact recap and a few relevant self-check questions. Put the numbered answers and explanations in a separate final section, preferably starting on a new page. Preserve the distinction between taught content, necessary explanations and optional enrichment. Include the context needed to understand diagrams, examples and references without opening a link. Keep source attribution readable; private source paths and hidden comments are not learner-facing explanation.
* **Set readable print defaults.** Use portrait A4 (210 x 297 mm), selectable/searchable body text, properly rendered formulas and precise diagrams. Typeset the text rather than generating whole pages as images. Start with about 11-12 pt body text and at least 15 mm margins; inspect actual-size readability. Use white backgrounds, restrained ink, labels/patterns as well as color, and grayscale-legible figures. Provide modest writing space where useful. Landscape pages are an explicit layout choice for a genuinely wide diagram, not the default inherited from the presentation format.
* **Use a clear typographic hierarchy.** Use one legible text family for prose, headings and attribution labels, with real regular, italic and bold weights and full coverage of the learning language. Keep explanations as readable as the core text; only secondary author/source labels are smaller and dark gray. Choose separate mathematical, code and symbol fonts where needed. Bundle reproducible licensed fonts with the renderer and embed them in the PDF; test accents, symbols and extracted text. Preserve the first-page banner without repeating it on every page.
* **Control length by the learning task.** Estimate the length before layout. Follow a requested page budget when the core and explanations remain readable; otherwise propose a smaller scope or natural parts. Do not shrink type, omit needed steps, add filler or create a long book solely to meet a count. No separate decorative cover is required. Presentation slide-count limits do not apply to prose handouts.
* **Check the final PDF.** Check source fidelity and core coverage, question/answer agreement, numbering, accents, mathematical symbols, reading order and copy/extracted text. Render and inspect every final page, including grayscale readability, margins, page breaks, clipped content, diagrams and captions. Keep headings with their text and essential figures with their explanation; links must not be required for the core learning task. OCR or a text extraction alone is not visual verification. A significant unresolved error keeps the handout a draft.
* **Version and deliver.** Keep the topic identifiable on every page with a modest running title; show the preparation date and page number unobtrusively. Put exact version identifiers in PDF metadata, the content-addressed filename and private generation record rather than the learner-facing prose. Keep exact wiki source versions/hashes, source attribution, editable document input, asset references and verification results in the private generation record. Treat the PDF as a versioned derivative, not a second authoritative wiki. A relevant wiki correction makes the related handout due for review; never silently replace a file behind a versioned filename. Use the configured private media storage and access checks, while keeping small editable inputs and provenance in Git. New images are optional and obey the existing authorization, visual-evidence and spending rules.

## Canonical input and publication boundary

Ordinary topic/chapter print is a versioned derivative of the existing canonical Markdown, selected in a declared order; it does not ask a model to rewrite the same lesson or silently invent missing teaching content. Keep text, formulas, sources and accepted images traceable to that revision. Include the self-test answers explicitly in the final answer section, regardless of screen disclosure state. A separately requested pedagogical rewrite is a separate content task. Apply the private/public source and asset restrictions to the printed artifact too; a private print is not permission for public PDF publication. This policy defines the result, not an installed PDF pipeline.
